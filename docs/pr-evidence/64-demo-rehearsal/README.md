## #249: "What Jev chose" panel (step 3)

Working on `main`:

- It appears under a rival's decision with `?demo` and the server's `DEMO_MODE=1` (`GET /api/ai/status` reported `"demo":true`). It listed the options in plain words with Jev's probability rounded to two decimals, the option taken marked "Chosen", "Jev decided.", "Jev's confidence: 0.86", the note "These numbers are Jev's own output, rounded to two decimals. - The same two-rival game without `?demo` showed no panel, no banner and no Prepared scenarios button, over 27 rival actions (`s03-2`).
- A server started without `DEMO_MODE` reported `"demo":false`. The unit tests for that case (`ai/ai.test.ts`, "the demo detail" and `DEMO_MODE=%j`; `web/src/DemoGate.test.tsx`) passed in the rerun below.

**What could not be exercised.** There is no Jev key in the sandbox, so no live Jev answer was seen. To see one anyway, a scratch server (not committed) ran the real `createApp` and the real orchestrator decider with the repo's own `createFakeJevClient` (`ai/jev/fake.ts`) in place of the SDK client, and skipped only the "is a key set?" check. Its answers are deterministic and made up (one option at 20 times the weight of the others), so the numbers in `s03-1` show the panel and the wiring, not how Jev plays. No key variable was set anywhere. Not seen in the browser: the Sell Phase panel (confidence is null there; covered by the web unit tests), a Deal response (not a Jev question yet) and a phone viewport.

## Step 7 detail

- Mid-game flip: the scratch server flipped `JEV_ENABLED` while a one-human game ran. `GET /api/ai/status` then reported `"jevEnabled":false,"backupOnly":true,"reason":"disabled"`; the next rival decision showed "Backup bot mode", and after the second rival decided the banner read "Every AI rival is using the backup bot. The variable is read per request, but a running server cannot have its environment changed, so on the real server the kill switch is a restart.

## Findings

1. **Step 6: the scene shows memory, not its effect on negotiation.** In "A promise the rival broke" the rival broke a promise to the human, so the human's trust in the rival is −2. The rival's willingness to promise again is its loyalty plus its own trust in the asker minus promises the asker broke to it (`ai/fallback/policy.ts`, `promiseTrustStep`, `promiseGrudge`; spec §4.8), and neither is set by this scene, so the refusal in `s06-2` is the rival's personality, not the memory. To show the effect, a scene would have the human break a promise to the rival and then ask for a new one. Spec §3 caps the list at "two to four" scenarios and the list already has four, so that is a spec decision (see the pull request), not a fix.
2. **Step 8: there is nothing to show as a graph.** `docs/report/README.md` is an outline of where figures will come from; the committed results are markdown tables (`docs/c4-300-game-report.md`, `docs/experiments/c5-policy-results.md`, `docs/jev-spike-report.md`, `docs/playtest/g1/ai-latency.md`), and spec §10 puts "decorative graphs" on the cut list. Live latency, fallback rate and actual spend need a key and a log (`logs/jev-decisions.jsonl`, `logs/jev-usage.jsonl`, both git-ignored), and the Jev-in-the-loop set (#62) is pending. Whether step 8 means a chart or the tables is a decision (see the pull request).
3. **No demo runbook.** `DEMO_MODE` and `?demo` appeared only in `.env.example`, `ai/README.md` and the spec. Fixed: the root `README.md` now has a "Demo mode" section.
4. **A stale comment** in `web/src/game/fakeJevAnswer.ts` said no server sends the detail yet. Fixed (comment only; `web/`, for Stream C).
5. **`npm test` is load-sensitive.** On a clean install, with other work running (load average 17 on 12 cores), 44 tests in 19 files failed on 5 s timeouts or on elements not found in time. The same 19 files passed (557 tests) with `--testTimeout=120000 --maxWorkers=3`. A later full run with `--testTimeout=60000` and the default workers (load average about 6 to 10) left 3 failures, all in `web/src/board/BoardScreen.test.tsx`, whose tests set their own 15, 30 and 60 s limits (the CLI option does not override those); that file passes by itself (3 tests, 31 s). This is the kind of timeout `docs/release/engine-triage.md` ET-05 records, not a regression. No test or `vitest.config.ts` change was made.
6. **Home hides Prepared scenarios behind a saved game.** With a saved game, `?demo` Home shows only "Continue this game?"; the list is reached by New game, then Back. Not specified either way in §3; noted for Stream C.
