# C5 policy evidence rows

The sanitized rows behind [`c5-policy-results.md`](../c5-policy-results.md), kept so a reader can check the published SHA-256 values. Spec §8 (Simulation, Critic), §9 (sim limits), §10 C5. Plan: [`c5-policy-plan.md`](../c5-policy-plan.md).

A game row holds identifiers, counts, outcomes and provenance only. No row carries a server key, a path or hidden information; every file was scanned for key names, paths and addresses before it was committed.

## Check

From the repository root at a revision that contains `5b96619`, with Node 24:

```bash
cd docs/experiments/c5-policy-evidence
sha256sum *.jsonl *.json
cd ../../..
out=$(mktemp -d)
sha=5b9661923006809e746053191d1dad1705d1bfd4
node --import tsx docs/experiments/c5-policy-evidence/analyze.mjs \
  docs/experiments/c5-policy-evidence/held-out-games.jsonl "$out/held-out" $sha
node --import tsx docs/experiments/c5-policy-evidence/analyze.mjs \
  docs/experiments/c5-policy-evidence/train-games.jsonl "$out/train" $sha 101004 3
sha256sum "$out"/*
```

`analyze.mjs` reads the manifest from `git show <sha>:sim/experiments/c5-plan.json`, because the manifest on later revisions has a different hash: its ledger and notes were edited after the run. It stops at the first row that disagrees with the manifest.

Regenerating the pair rows and analysis output from the committed game rows gave byte-identical files (the SHA-256 values above) when this was checked. That check replays no game. The game rows themselves were not regenerated by playing the seeds again; the reviewer of the results pull request replayed one held-out cell and matched its published numbers.
